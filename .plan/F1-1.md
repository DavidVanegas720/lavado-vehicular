# Plan F1-1 — Fundación y componentes base

Rebanada: `docs/rebanadas.md` → "F1-1". Requiere FP-0 cerrado y mergeado. Rama: `tarea/f1-1-fundacion`.
Objetivo: el frontend arranca, tiene layout, navegación, tema claro/oscuro, capa de mocks detrás del
cliente HTTP y un set cerrado de componentes reutilizables probados.

## Reglas para los agentes que ejecuten pasos

1. Leer `CLAUDE.md`, `docs/convenciones-codigo.md`, `docs/reglas-negocio.md`, este plan y
   `docs/registro/decisiones-tomadas.md` antes de tocar nada.
2. **Solo tocar los archivos que el paso declara como propios.** Si hace falta tocar otro, parar y avisar.
3. **Prohibido `pnpm add`/`remove`.** Todas las dependencias ya están desde FP-0. Si falta una, parar.
4. `export PATH=~/.local/bin:$PATH` en cada comando. Antes de entregar el paso:
   `pnpm lint && pnpm typecheck && pnpm test` verdes (o el subconjunto del paquete tocado).
5. Errores encontrados y su solución → `docs/registro/errores.md`. Decisiones menores →
   `docs/registro/decisiones-tomadas.md`. Asunciones de dominio → comentario `// P-X: se asume ...`.
6. No inventar reglas de negocio. Si un componente "necesita" una, parar y consultar.
7. El orquestador (no los agentes) hace commit al cerrar cada ola, tras `pnpm verificar` verde.

## Convenciones fijadas para esta rebanada

- Archivos `.vue` en `PascalCase` (`BotonPrincipal.vue`); el resto en `kebab-case`
  (`use-formato-moneda.ts` exporta `useFormatoMoneda`). Test junto al fuente (`*.test.ts`).
- Carpetas: `src/componentes/base/` (genéricos), `src/componentes/dominio/` (conocen el modelo),
  `src/componentes/layout/`, `src/composables/`, `src/vistas/`, `src/router/`, `src/api/`, `src/mocks/`,
  `src/tema/`, `src/estilos/`.
- Props en español `camelCase`. Toda etiqueta visible en español. Íconos: clases `pi pi-*` de primeicons.
- Componentes envuelven PrimeVue cuando exista el equivalente; Tailwind para layout. Nada de CSS
  custom salvo tokens y animaciones.
- Toda interacción: foco visible (`focus-visible:ring-2`), tap target ≥ 44×44 px, accesible por teclado.
- Animaciones: 150 ms micro, 250 ms página/modal, 400 ms listas; `ease-out` entrar, `ease-in` salir;
  todas anuladas con `prefers-reduced-motion: reduce` (bloque global de FP-0 + `motion-reduce:`).
- Tests con `@testing-library/vue` buscando por rol/texto; sin snapshots; cubrir variantes, estados,
  eventos (payload) y atributos ARIA.

### P1-B — Composables de dominio
**Archivos propios:** `src/composables/use-formato-moneda.ts`, `src/composables/use-dia-operativo.ts` (+tests).
- `useFormatoMoneda()` → funciones puras (formateadores `Intl` creados una vez a nivel de módulo):
  - `formatear(c: Centavos): string` → `"$ 30.000"` (es-CO, COP). Sin decimales si `c % 100 === 0`;
    con 2 decimales si no (comisiones pueden tener centavos).
  - `formatearSinSimbolo(c)` → `"30.000"`.
  - `parsearPesos(texto: string): Centavos | null` → toma solo dígitos (pesos enteros), devuelve
    `centavosDesdePesos(n)` de shared; `null` si vacío o fuera de rango seguro.
  - Nunca `parseFloat`, nunca división en el camino de dinero.
  - Tests: normalizar NBSP (` `) al comparar; `3_000_000 → "$ 30.000"`; `0`; `123_456 → "$ 1.234,56"`;
    `parsearPesos("30.000") === 3_000_000`; letras ignoradas; vacío → `null`.

  formatearDia(d), formatearHora(isoUtc) }`. **Solo envuelve `calcularDiaOperativo` de shared**; no

## Componentes: props, eventos y estados

Comunes a todo campo (`CampoBase` los implementa): `id?` (default `useId()`), `etiqueta` (obligatoria),
`ayuda?`, `error?: string | null`, `requerido?`, `deshabilitado?`. `<label for>`, `aria-invalid`,
`aria-describedby` (ayuda + error), `aria-required`; error con `aria-live="polite"`. Emiten
`update:modelValue` y `blur`.

| Componente | Props clave | Eventos | Estados / variantes a probar |
|---|---|---|---|
